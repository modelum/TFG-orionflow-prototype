Vista general de la arquitectura

El generador mantiene separadas tres responsabilidades: comprender la evolución, resolver la identidad original de los elementos y construir consultas CodeQL modulares.

Orquestación

Orion2CodeQL conserva el dispatch generateOperation(...). Reconoce cada SCO, consulta el contexto y delega la generación.

Identidad evolutiva

EvolutionContext separa nombre actual y nombre original. Así, un rename de entidad seguido de un rename de campo sigue buscando los símbolos que realmente existen en el código.

Generadores de consultas

EntityQueryRename, Delete y Split Entity.
FeatureQueryRename, Delete y Move Feature.
AttributeQueryCast Attribute, Cast Reference y Promote.
RelationshipQueryRename y Delete Relationship.
Regla de diseño: las clases Query construyen CodeQL; no gestionan el historial de evolución. El contexto se resuelve antes de delegar.

Principio de coherencia

Cada capa comprueba una propiedad distinta. Si una query contiene el texto esperado pero usa una API inexistente, falla la compilación CodeQL. Si compila pero enlaza el símbolo equivocado, fallan los fixtures SARIF. Si los perfiles se mezclan, falla la igualdad de conjuntos.

Unitarios de plantilla

Inspeccionan el QL generado para asegurar que aparece el predicado correcto y que no reaparecen patrones prohibidos. Son rápidos y localizan regresiones en la plantilla.

Integración del generador

Construye modelos Orion reales con EMF, ejecuta el transformador y comprueba nombres de archivos, módulos y resolución histórica.

Qué no demuestran por sí solos

Una aserción textual no demuestra que la API QL exista ni que el predicado encuentre resultados correctos. Por eso estas suites son la base, no el final de la validación.

Oráculo SARIF y coherencia entre perfiles

Cada hallazgo se normaliza mediante una identidad estable:

(ruleId, URI normalizada, línea/columna inicial y final, mensaje)

Positivos obligatorios

  • Regla concreta.
  • Fichero y rango de líneas.
  • Fragmento semántico del mensaje.
  • Símbolo resuelto esperado.

Negativos obligatorios

  • Clases homónimas no persistentes.
  • Strings iguales en APIs arbitrarias.
  • Propiedades de otra entidad.
  • Expresiones dinámicas no resolubles.

Invariantes de composición

InvarianteFallo que evita
Default = JPA explícitoCambio silencioso de compatibilidad CLI.
JPA no contiene resultados MongoAcoplamiento o import de adaptador indebido.
Mongo no contiene resultados JPAContaminación cruzada entre frameworks.
Both = conjunto(JPA ∪ Mongo)Pérdidas, extras o precedencia lógica incorrecta.
Sin identidades duplicadasDos caminos equivalentes reportando el mismo impacto.
Comparar solo el número total no basta: una pérdida y un falso positivo podrían compensarse. La comparación se realiza sobre conjuntos de identidades normalizadas.

Coste acotado

Call Graph se limita a dos saltos y el flujo global parte de un único campo CAST. La evaluación más lenta quedó en 6,0 s en el fixture.

Medición honesta

CodeQL eligió -Xmx3434M y 3660 MB off-heap, pero los logs no aportaron RSS máximo real. No se declara una cifra de memoria pico.

Criterios de aceptación de rendimiento

  • Separar compilación y evaluación para no atribuir el coste al predicado equivocado.
  • Ejecutar los perfiles sobre la misma base y hardware.
  • Comparar alertas junto con tiempo: una query rápida que pierde positivos no es válida.
  • Rechazar degradaciones extremas o impredecibles.
  • Preservar regex estáticas y limitar fuentes/sinks antes de añadir propagación.

Los tiempos son observaciones de una ejecución local sobre fixtures internos, no garantías para aplicaciones de mayor tamaño.

Extensiones V3.2 validadas

Las dos extensiones se incorporan automáticamente por SCO, sin introducir flags públicos nuevos.

CALL GRAPH · VALIDADO

Delete Relationship / Feature / Move

  • Dependencia directa y wrapper que consume el resultado.
  • Modificación indirecta de colección.
  • Uno y dos niveles, sin cierre transitivo general.
  • Overloads, herencia, despacho virtual y helpers privados.
  • Negativo: llamada cuyo resultado se descarta y no tiene efecto relevante.
  • Evidencia en mensaje: origen, llamador y profundidad.
GLOBAL DATAFLOW · VALIDADO

Solo CAST Attribute / Reference

  • Fuente exacta: campo/getter afectado.
  • Argumentos, retornos, variables y llamadas encadenadas.
  • Sink ligado al tipo anterior, no cualquier uso.
  • Varios parámetros del mismo tipo y referencias similares.
  • Negativo: consumidor compatible con el tipo nuevo.
  • Regresión: ninguna SCO no-CAST activa flujo global.

Checklist de cierre

Para cada cambio

  • Test unitario de la plantilla.
  • Fixture positivo y negativo.
  • Generación en jpa/mongo/both.
  • Compilación con CodeQL 2.27.2.
  • Ejecución y comprobación SARIF.
  • Medición separada de coste.

Para una release

  • Default idéntico a JPA.
  • Both igual a unión exacta.
  • EvolutionContext encadenado.
  • Sin duplicados ni cruces de framework.
  • Ground truth intacto.
  • Documentación y limitaciones actualizadas.
